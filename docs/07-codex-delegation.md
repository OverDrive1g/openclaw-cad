# 07. Делегирование в Codex CLI

Codex хорошо подходит для цикличной генерации геометрии: «сделай деталь →
получи факты → поправь». Он читает проектный `AGENTS.md` и умеет ходить в тот же
FreeCAD MCP. Но у него есть свои грабли, и проверять его нужно по файлам, а не
по финальному отчёту.

## Когда делегировать

- Много однотипных деталей или итераций.
- Рутинная правка параметров и пересборка.
- Задача, где нужен большой объём кода, а не творческое решение.

Не делегируйте:

- выбор посадок и критичных размеров без ТЗ;
- финальную проверку — числа и топологию проверяйте сами;
- задачи, где нужен доступ к локальной сети/БД: песочница Codex часто их режет.

## Конфиг

`<repo>/.codex/config.toml`:

```toml
[mcp_servers.freecad]
command = "uv"
args = ["run", "--project", "/path/to/freecad-addon-robust-mcp-server", "freecad-mcp"]

[mcp_servers.freecad.env]
FREECAD_MODE = "xmlrpc"

[projects."/path/to/repo"]
trust_level = "trusted"
```

## Запуск

Короткий однострочный промпт:

```bash
cd /path/to/repo
codex exec --approve-for-me --skip-git-repo-check "Сделай ..."
```

Длинный промпт передавайте через stdin, иначе парсер может развалиться на
кавычках и русских фразах:

```bash
cat <<'PROMPT' | codex exec --approve-for-me --skip-git-repo-check -
<многострочный бриф>
PROMPT
```

Почему `--approve-for-me`: MCP-вызовы требуют approval. Флаг несовместим с
`-s`, поэтому используется вместо песочницы. `--skip-git-repo-check` нужен для
каталога, который Codex не считает доверенным git-репозиторием.

## Бриф: обязательные пункты

```text
ЗАДАЧА
Спроектировать <деталь> по размерам:
- ...
- ...

СРЕДА
- FreeCAD запущен, мост на localhost:9875.
- Первый шаг: mcp__freecad__get_connection_status. Если не connected — стоп и отчёт.
- Геометрия только через FreeCAD Part API. Никаких OpenSCAD/cadgen/слайсеров.

ПРАВИЛА РАБОТЫ
- 1 вызов execute_code = 1–3 булевы операции.
- После каждого этапа: doc.recompute() и doc.saveAs(<путь>).
- Параметры — именованные переменные в начале скрипта.
- Не трогать <чужие файлы/детали>.
- Не коммитить.

ПРОВЕРКА
- Вернуть габариты, объём, число solids, isValid.
- Скриншот обязателен.
- Ожидаемый объём: <расчёт> ±0.5%.

ОТЧЁТ
В конце: что сделал, какие файлы сохранены, факты проверки, что не проверено.
```

## Правила, которые приходится повторять

- **Мелкие транзакции.** Codex по умолчанию льёт всю деталь в один вызов:
  это ловит лимит ответа MCP и OOM FreeCAD. Пропишите 1–3 операции и `saveAs`
  после каждого этапа прямо в брифе.
- **Проверка по файлам.** Отчёт может быть красивым, а сохранённым — только один
  документ. После запуска:

  ```bash
  find cad -name '*.fcstd' -printf '%p %s bytes\n'
  git status --short
  git log --oneline -5
  ```

- **Codex может закоммитить** вопреки запрету. Смотрите `git log`, а не только
  `git status`.
- **Дубликаты импортов/регистраций** — типичная проблема после больших правок.
  Проверяйте диффом, а не доверием.
- **Пустой прогон** бывает из-за падения модели. Иногда достаточно повторить
  тот же бриф.
- **Не сдавайтесь после exit code.** Exit 1 может означать сетевой сбой
  песочницы при нормальных правках; exit 0 — отсутствие файлов.

## Разделение труда

Хорошая схема:

1. Вы даёте ТЗ и ограничения.
2. Codex генерирует/правит геометрию мелкими шагами.
3. Агент или вы проверяете числа, топологию и DFM.
4. Codex правит по конкретному списку `fail`.
5. Финальную проверку и экспорт делаете вы.

Codex не должен быть единственным судьёй качества. Его сильная сторона — скорость
итераций, а не ответственность за посадки.
